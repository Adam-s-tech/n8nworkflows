# Score ATS candidates and enroll top matches into Supabase outreach campaigns

### 1. Workflow Overview

This workflow automates the ingestion, enrichment, sourcing, scoring, and suppression-filtering of job candidates from an Applicant Tracking System (ATS), preparing them for an outbound recruitment campaign managed in Supabase. It targets recruitment agencies and internal talent acquisition teams to streamline candidate shortlisting and eliminate manual sorting.

The workflow logic is divided into six functional blocks:
- **1.1 Input Reception & Configuration:** Receives job order payloads via incoming webhooks or manual triggers, applies global settings, and normalizes job fields using a flexible vendor map.
- **1.2 AI-Powered Job Enrichment:** Evaluates whether job descriptions require AI processing based on keyword thresholds, utilizing Anthropic’s API to extract required and preferred skills.
- **1.3 Candidate Sourcing & Normalization:** Queries the connected ATS (or falls back to a built-in sample candidate pool), normalizes contact numbers to E.164 format, collapses duplicates, and scores candidates against job requirements.
- **1.4 Compliance Gate & Suppression:** Checks candidates against Supabase engagement history to filter out opt-outs, recent touch cooldowns, active enrollments elsewhere, and scores falling beneath defined thresholds.
- **1.5 Database Persistence:** Upserts job orders, campaigns, and candidate records into Supabase, links record UUIDs, and inserts campaign enrollments with scheduled first outreach touches.
- **1.6 Execution Summary & Notification:** Aggregates run metrics and optionally posts a launch summary report to a Slack channel via incoming webhooks.

### 2.1 Input Reception & Configuration

#### Overview
This block serves as the entry point for the workflow, capturing job orders from external ATS webhooks or manual triggers, and injecting global engine configurations.

#### Nodes Involved
- `Job order created`
- `Run it now`
- `config`
- `read the job order`
- `job order usable?`
- `STOP: job order not usable`

#### Node Details

- **`Job order created`**
  - **Type & Technical Role:** `n8n-nodes-base.webhook` (Webhook trigger).
  - **Configuration:** Configured to accept HTTP `POST` requests at path `stratton-job-order` with response mode set to respond on the last node.
  - **Expressions/Variables:** None.
  - **Connections:** Output connects to `config`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** Webhook delivery failures from the ATS; unauthenticated requests (handled by external ATS security settings).

- **`Run it now`**
  - **Type & Technical Role:** `n8n-nodes-base.manualTrigger` (Manual execution trigger).
  - **Configuration:** Default manual execution parameters.
  - **Expressions/Variables:** None.
  - **Connections:** Output connects to `config`.
  - **Version Requirements:** Type version 1.
  - **Edge Cases/Failures:** None.

- **`config`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Defines global constants including client identifiers, Supabase connection details, ATS vendor configurations, field mappings, AI model settings, scoring weights, and safety switches (`DEMO_MODE`, `TEST_RUN`).
  - **Expressions/Variables:** Evaluates runtime modes based on demo flags and credential presence.
  - **Connections:** Input from `Job order created` or `Run it now`; output connects to `read the job order`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** Syntax errors in configuration JavaScript; unhandled null references if accessed before initialization.

- **`read the job order`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Normalizes incoming webhook payloads or manual test inputs into a standardized job specification using the `ATS_FIELDS.job` map defined in the config node. Handles dotted object paths, converts skill lists into clean arrays, and extracts pay rates and location attributes.
  - **Expressions/Variables:** Reads configuration from `$('config')` and raw input payloads via `$input.first()`.
  - **Connections:** Input from `config`; output connects to `job order usable?`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** Malformed JSON structures or unexpected schema changes from ATS vendors resulting in missing job titles or IDs.

- **`job order usable?`**
  - **Type & Technical Role:** `n8n-nodes-base.if` (Conditional evaluation node).
  - **Configuration:** Evaluates whether `_job_usable` evaluates to `true`.
  - **Expressions/Variables:** `={{ $json._job_usable }}`
  - **Connections:** Input from `read the job order`; `true` branch connects to `AI worth calling?`, `false` branch connects to `STOP: job order not usable`.
  - **Version Requirements:** Type version 2.2.
  - **Edge Cases/Failures:** Boolean evaluation errors due to loose type validation settings.

- **`STOP: job order not usable`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Terminates the workflow path when a job payload lacks essential identifiers (e.g., job ID or title), returning diagnostic details comparing received keys against the active field map.
  - **Expressions/Variables:** Accesses payload properties and configuration details.
  - **Connections:** Input from `job order usable?` (`false` branch); output connects to `End`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** None.

### 2.2 AI-Powered Job Enrichment

#### Overview
This block checks whether a job order requires AI enrichment based on skill count thresholds, using Anthropic's Messages API to extract structured requirements from unstructured job descriptions when necessary.

#### Nodes Involved
- `AI worth calling?`
- `[cred] AI - read the job description`
- `apply the AI requirements`
- `STOP: keyword rules only`
- `the job spec`

#### Node Details

- **`AI worth calling?`**
  - **Type & Technical Role:** `n8n-nodes-base.if` (Conditional evaluation node).
  - **Configuration:** Evaluates whether `_ai_worth_calling` is `true`.
  - **Expressions/Variables:** `={{ $json._ai_worth_calling }}`
  - **Connections:** Input from `job order usable?` (`true` branch); `true` branch connects to `[cred] AI - read the job description`, `false` branch connects to `STOP: keyword rules only`.
  - **Version Requirements:** Type version 2.2.
  - **Edge Cases/Failures:** Boolean evaluation errors.

- **`[cred] AI - read the job description`**
  - **Type & Technical Role:** `n8n-nodes-base.httpRequest` (HTTP integration node).
  - **Configuration:** Sends a `POST` request to `https://api.anthropic.com/v1/messages` with model parameters and prompt instructions to extract required skills, nice-to-haves, certifications, and shift preferences. Configured with a 20-second timeout, `neverError` response handling, and up to 3 retry attempts with a 2-second interval.
  - **Expressions/Variables:** Uses `={{ JSON.stringify(...) }}` to construct the request body using configuration values for AI model, effort level, and max skills, while injecting the API key into the `x-api-key` header.
  - **Connections:** Input from `AI worth calling?` (`true` branch); output connects to `apply the AI requirements`.
  - **Version Requirements:** Type version 4.2.
  - **Edge Cases/Failures:** API authentication errors, rate-limiting (`429`), upstream service outages, or timeouts. Mitigated by `neverError` and retry configurations.

- **`apply the AI requirements`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Sanitizes and parses the AI text response into structured JSON, extracting skill lists and merging them with existing ATS skill requirements. Includes fallback mechanisms if JSON parsing fails or if the API returns an error structure.
  - **Expressions/Variables:** Reads data from `$('config')`, `$('read the job order')`, and `$input.first()`.
  - **Connections:** Input from `[cred] AI - read the job description`; output connects to input index 0 of `the job spec`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** Unparsable model responses (e.g., markdown code blocks or conversational text prepended to JSON). Handled via robust string extraction logic.

- **`STOP: keyword rules only`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Passes the job specification through untouched when AI enrichment is bypassed or disabled, appending explanatory metadata regarding why the step was skipped.
  - **Expressions/Variables:** Reads configuration and input parameters.
  - **Connections:** Input from `AI worth calling?` (`false` branch); output connects to input index 1 of `the job spec`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** None.

- **`the job spec`**
  - **Type & Technical Role:** `n8n-nodes-base.merge` (Data merger node).
  - **Configuration:** Merges incoming paths from either `apply the AI requirements` or `STOP: keyword rules only`.
  - **Expressions/Variables:** None.
  - **Connections:** Inputs from `apply the AI requirements` and `STOP: keyword rules only`; output connects to `ATS connected?`.
  - **Version Requirements:** Type version 3.
  - **Edge Cases/Failures:** None.

### 2.3 Candidate Sourcing & Normalization

#### Overview
This block queries the configured ATS for candidate records or falls back to a bundled sample pool, normalizes telephone numbers into E.164 format, collapses duplicate entries, and transparently scores each candidate against the job specifications.

#### Nodes Involved
- `ATS connected?`
- `[cred] ATS - search candidates`
- `STOP: using the sample pool`
- `one candidate pool`
- `normalise the candidates`
- `score against the job order`

#### Node Details

- **`ATS connected?`**
  - **Type & Technical Role:** `n8n-nodes-base.if` (Conditional evaluation node).
  - **Configuration:** Evaluates whether `ats_enabled` in the config is `true`.
  - **Expressions/Variables:** `={{ $('config').first().json.ats_enabled }}`
  - **Connections:** Input from `the job spec`; `true` branch connects to `[cred] ATS - search candidates`, `false` branch connects to `STOP: using the sample pool`.
  - **Version Requirements:** Type version 2.2.
  - **Edge Cases/Failures:** Boolean evaluation errors.

- **`[cred] ATS - search candidates`**
  - **Type & Technical Role:** `n8n-nodes-base.httpRequest` (HTTP integration node).
  - **Configuration:** Sends a `POST` request to the ATS search endpoint using dynamic query parameters based on required skills or job titles. Configured with a 20-second timeout, `neverError` response handling, and up to 3 retry attempts with a 2-second interval.
  - **Expressions/Variables:** Uses `={{ JSON.stringify(...) }}` to construct payloads with search queries, mapped candidate fields, and search limits, authenticating via Bearer tokens or vendor-specific headers (e.g., `BhRestToken`).
  - **Connections:** Input from `ATS connected?` (`true` branch); output connects to input index 0 of `one candidate pool`.
  - **Version Requirements:** Type version 4.2.
  - **Edge Cases/Failures:** ATS authentication failure, invalid search syntax, pagination limits, or network timeouts.

- **`STOP: using the sample pool`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Supplies a static array of mock candidate records representing various test scenarios (active candidates, duplicates, opted-out records, placed candidates, landline numbers, and cooldown states) when no ATS is connected.
  - **Expressions/Variables:** None.
  - **Connections:** Input from `ATS connected?` (`false` branch); output connects to input index 1 of `one candidate pool`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** None.

- **`one candidate pool`**
  - **Type & Technical Role:** `n8n-nodes-base.merge` (Data merger node).
  - **Configuration:** Combines data streams from either the live ATS search or the sample candidate pool.
  - **Expressions/Variables:** None.
  - **Connections:** Inputs from `[cred] ATS - search candidates` and `STOP: using the sample pool`; output connects to `normalise the candidates`.
  - **Version Requirements:** Type version 3.
  - **Edge Cases/Failures:** None.

- **`normalise the candidates`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Standardizes candidate records by mapping vendor fields, filtering out excluded statuses (e.g., Placed, Blacklisted), converting phone numbers into E.164 format, and deduplicating records sharing identical phone numbers, emails, or names.
  - **Expressions/Variables:** Reads configuration and candidate items via `$input.all()`.
  - **Connections:** Input from `one candidate pool`; output connects to `score against the job order`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** Unrecognized phone number formats resulting in null numbers; inconsistent nested properties across different ATS schemas.

- **`score against the job order`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Computes a transparent match score for each candidate based on weighted criteria including required skills, preferred skills, title overlap, location proximity, recent activity status, and mobile availability. Ranks candidates in descending order.
  - **Expressions/Variables:** Reads configuration matching weights, job specifications, and normalized candidate records.
  - **Connections:** Input from `normalise the candidates`; output connects to `Supabase connected?`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** Missing skill arrays or malformed numerical weights resulting in NaN score calculations.

### 2.4 Compliance Gate & Suppression

#### Overview
This block checks candidate records against Supabase engagement history to enforce compliance rules—filtering out opt-outs, recent touch cooldowns, active campaigns, and scores below the defined minimum threshold.

#### Nodes Involved
- `Supabase connected?`
- `[cred] Supabase - engagement history`
- `read the engagement history`
- `STOP: no engagement history`
- `one engagement history`
- `decide who gets contacted`

#### Node Details

- **`Supabase connected?`**
  - **Type & Technical Role:** `n8n-nodes-base.if` (Conditional evaluation node).
  - **Configuration:** Evaluates whether `supabase_enabled` in the config is `true`.
  - **Expressions/Variables:** `={{ $('config').first().json.supabase_enabled }}`
  - **Connections:** Input from `score against the job order`; `true` branch connects to `[cred] Supabase - engagement history`, `false` branch connects to `STOP: no engagement history`.
  - **Version Requirements:** Type version 2.2.
  - **Edge Cases/Failures:** Boolean evaluation errors.

- **`[cred] Supabase - engagement history`**
  - **Type & Technical Role:** `n8n-nodes-base.httpRequest` (HTTP integration node).
  - **Configuration:** Calls a Supabase Postgres RPC function (`engagement_history`) via a `POST` request to retrieve opt-outs, recent contact history, and active enrollments in a single database round trip. Configured with a 20-second timeout, `neverError` response handling, and up to 3 retry attempts with a 2-second interval.
  - **Expressions/Variables:** Uses `={{ JSON.stringify(...) }}` to send client ID, job ID, and an array of candidate phone numbers. Authenticated via `apikey` and `Authorization` headers.
  - **Connections:** Input from `Supabase connected?` (`true` branch); output connects to `read the engagement history`.
  - **Version Requirements:** Type version 4.2.
  - **Edge Cases/Failures:** Supabase downtime, network timeouts, invalid RPC function signatures, or missing database permissions.

- **`read the engagement history`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Processes the JSON response from the engagement history RPC, structuring opt-out lists, last touch timestamps, active phone indexes, and enrolled ATS IDs into a standardized format.
  - **Expressions/Variables:** Reads raw HTTP responses from `$input.first()`.
  - **Connections:** Input from `[cred] Supabase - engagement history`; output connects to input index 0 of `one engagement history`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** Malformed RPC output structures or HTTP error responses disguised as 200 OK payloads.

- **`STOP: no engagement history`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Provides fabricated engagement history data when `DEMO_MODE` is active, or returns an empty suppression stub with warning metadata if Supabase is unconfigured.
  - **Expressions/Variables:** Reads configuration settings.
  - **Connections:** Input from `Supabase connected?` (`false` branch); output connects to input index 1 of `one engagement history`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** None.

- **`one engagement history`**
  - **Type & Technical Role:** `n8n-nodes-base.merge` (Data merger node).
  - **Configuration:** Merges engagement history streams from either Supabase or the fallback stub node.
  - **Expressions/Variables:** None.
  - **Connections:** Inputs from `read the engagement history` and `STOP: no engagement history`; output connects to `decide who gets contacted`.
  - **Version Requirements:** Type version 3.
  - **Edge Cases/Failures:** None.

- **`decide who gets contacted`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Acts as the primary compliance gate. Evaluates candidates against strict rejection criteria in sequence: missing mobile numbers, opt-out lists, existing campaign enrollments, active status elsewhere, cooldown expiration windows, and minimum score floors. Retains the top $N$ eligible candidates and holds the remainder with specific rejection reasons.
  - **Expressions/Variables:** Accesses configuration thresholds, job specifications, scored candidates, and engagement history data.
  - **Connections:** Input from `one engagement history`; output connects to `anyone to enroll?`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** Unmatched phone number string formats leading to bypasses in opt-out checks (mitigated by E.164 normalization).

- `[cred] Supabase - upsert the candidates`
- `link the enrollments`
- `[cred] Supabase - insert the enrollments`

  - **Connections:** Input from `writing to the database?` (`true` branch); output connects to `[cred] Supabase - upsert the campaign`.
  - **Version Requirements:** Type version 4.2.

  - **Type & Technical Role:** `n8n-nodes-base.httpRequest` (HTTP integration node).
  - **Configuration:** Sends a `POST` request to upsert campaign records into Supabase (`/rest/v1/campaigns?on_conflict=client_id,idempotency_key`). Configured with a 20-second timeout, `neverError` response handling, and up to 3 retry attempts with a 2-second interval.
  - **Expressions/Variables:** Uses `={{ JSON.stringify([$('rows for supabase').first().json.campaign]) }}` for the request body, authenticating via API keys and setting `Prefer: resolution=merge-duplicates,return=representation`.
  - **Connections:** Input from `[cred] Supabase - upsert the job order`; output connects to `[cred] Supabase - upsert the candidates`.
  - **Version Requirements:** Type version 4.2.
  - **Edge Cases/Failures:** Unique index conflicts or database connection drops.

- **`[cred] Supabase - upsert the candidates`**
  - **Type & Technical Role:** `n8n-nodes-base.httpRequest` (HTTP integration node).
  - **Configuration:** Sends a `POST` request to upsert candidate records into Supabase (`/rest/v1/candidates?on_conflict=client_id,ats_candidate_id`). Configured with a 20-second timeout, `neverError` response handling, and up to 3 retry attempts with a 2-second interval.
  - **Expressions/Variables:** Uses `={{ JSON.stringify($('rows for supabase').first().json.candidates) }}` for the request body, authenticating via API keys and setting `Prefer: resolution=merge-duplicates,return=representation`.
  - **Connections:** Input from `[cred] Supabase - upsert the campaign`; output connects to `link the enrollments`.
  - **Version Requirements:** Type version 4.2.
  - **Edge Cases/Failures:** Batch constraint failures or validation errors on candidate phone formats.

- **`link the enrollments`**
  - **Type & Technical Role:** `n8n-nodes-base.code` (JavaScript execution node).
  - **Configuration:** Resolves natural keys in prepared enrollment stubs into newly minted Supabase UUIDs returned by the preceding campaign, job order, and candidate upsert responses.
  - **Expressions/Variables:** Reads data from configuration, prepared rows, and upstream HTTP response nodes.
  - **Connections:** Input from `[cred] Supabase - upsert the candidates`; output connects to `[cred] Supabase - insert the enrollments`.
  - **Version Requirements:** Type version 2.
  - **Edge Cases/Failures:** Missing ID attributes in upstream responses due to partial upsert failures.

- **`[cred] Supabase - insert the enrollments`**
  - **Type & Technical Role:** `n8n-nodes-base.httpRequest` (HTTP integration node).
  - **Configuration:** Sends a `POST` request to insert enrollment records into Supabase (`/rest/v1/enrollments?on_conflict=campaign_id,candidate_id`). Configured with a 20-second timeout, `neverError` response handling, and up to 3 retry attempts with a 2-second interval.

  - **Connections:** Input from `link the enrollments`; output connects to `build the launch summary`.
  - **Version Requirements:** Type version 4.2.
  - **Edge Cases/Failures:** Foreign key constraint violations or duplicate conflict collisions.

### 4. Reproducing the Workflow from Scratch

Follow this step-by-step procedure to rebuild the workflow manually in n8n:

1. **Create Trigger Nodes:**
   - Add a **Webhook** node (`Job order created`). Set path to `stratton-job-order`, HTTP method to `POST`, and response mode to `Last Node`.
   - Add a **Manual Trigger** node (`Run it now`).

2. **Add Configuration Node:**
   - Add a **Code** node (`config`). Paste the configuration JavaScript setting up client slugs, Supabase connection details, ATS field mappings, AI model settings, matching weights, outreach sequences, and safety switches (`DEMO_MODE = true`).
   - Connect both `Job order created` and `Run it now` outputs to `config`.

3. **Add Job Parsing & Validation Nodes:**
   - Add a **Code** node (`read the job order`), connected downstream from `config`.
   - Add an **If** node (`job order usable?`), connected from `read the job order`. Set condition to evaluate `{{ $json._job_usable }} == true`.
   - Add a **Code** node (`STOP: job order not usable`), connected to the `false` branch of `job order usable?`. Connect its output to an **End** (`NoOp`) node.

4. **Add AI Enrichment Branch:**
   - Add an **If** node (`AI worth calling?`), connected from the `true` branch of `job order usable?`. Set condition to evaluate `{{ $json._ai_worth_calling }} == true`.
   - Add an **HTTP Request** node (`[cred] AI - read the job description`), connected to the `true` branch of `AI worth calling?`. Set method to `POST`, URL to `https://api.anthropic.com/v1/messages`, configure headers (`x-api-key`, `anthropic-version: 2023-06-01`, `Content-Type: application/json`), and supply the JSON body payload. Enable `neverError` and configure 3 retry attempts.
   - Add a **Code** node (`apply the AI requirements`), connected from `[cred] AI - read the job description`.
   - Add a **Code** node (`STOP: keyword rules only`), connected to the `false` branch of `AI worth calling?`.
   - Add a **Merge** node (`the job spec`). Connect `apply the AI requirements` to input index 0 and `STOP: keyword rules only` to input index 1.

5. **Add ATS Sourcing & Scoring Nodes:**
   - Add an **If** node (`ATS connected?`), connected from `the job spec`. Set condition to evaluate `{{ $('config').first().json.ats_enabled }} == true`.
   - Add an **HTTP Request** node (`[cred] ATS - search candidates`), connected to the `true` branch of `ATS connected?`. Set method to `POST`, URL to `={{ $('config').first().json.ats_base_url }}/search/Candidate`, configure authorization headers and JSON body parameters. Enable `neverError` and configure 3 retry attempts.
   - Add a **Code** node (`STOP: using the sample pool`), connected to the `false` branch of `ATS connected?`.
   - Add a **Merge** node (`one candidate pool`). Connect `[cred] ATS - search candidates` to input index 0 and `STOP: using the sample pool` to input index 1.
   - Add a **Code** node (`normalise the candidates`), connected from `one candidate pool`.
   - Add a **Code** node (`score against the job order`), connected from `normalise the candidates`.

6. **Add Compliance Gate & Suppression Nodes:**
   - Add an **If** node (`Supabase connected?`), connected from `score against the job order`. Set condition to evaluate `{{ $('config').first().json.supabase_enabled }} == true`.
   - Add an **HTTP Request** node (`[cred] Supabase - engagement history`), connected to the `true` branch of `Supabase connected?`. Set method to `POST`, URL to `={{ $('config').first().json.supabase_url }}/rest/v1/rpc/engagement_history`, configure headers (`apikey`, `Authorization`, `Content-Type`) and JSON body parameters. Enable `neverError` and configure 3 retry attempts.
   - Add a **Code** node (`read the engagement history`), connected from `[cred] Supabase - engagement history`.
   - Add a **Code** node (`STOP: no engagement history`), connected to the `false` branch of `Supabase connected?`.
   - Add a **Merge** node (`one engagement history`). Connect `read the engagement history` to input index 0 and `STOP: no engagement history` to input index 1.
   - Add a **Code** node (`decide who gets contacted`), connected from `one engagement history`.

7. **Add Database Persistence Nodes:**
   - Add an **If** node (`anyone to enroll?`), connected from `decide who gets contacted`. Set condition to evaluate `{{ $json._has_enrollments }} == true`.
   - Add a **Code** node (`STOP: nobody eligible`), connected to the `false` branch of `anyone to enroll?`. Connect its output to the `End` node.
   - Add a **Code** node (`rows for supabase`), connected from the `true` branch of `anyone to enroll?`.
   - Add an **If** node (`writing to the database?`), connected from `rows for supabase`. Set condition to evaluate `{{ $json._write }} == true`.
   - Add a **Code** node (`STOP: preview - nothing enrolled`), connected to the `false` branch of `writing to the database?`.
   - Add an **HTTP Request** node (`[cred] Supabase - upsert the job order`), connected to the `true` branch of `writing to the database?`. Set method to `POST`, URL to `={{ $('config').first().json.supabase_url }}/rest/v1/job_orders?on_conflict=client_id,ats_job_id`, headers (`apikey`, `Authorization`, `Content-Type`, `Prefer: resolution=merge-duplicates,return=representation`), and body. Enable `neverError` and 3 retries.
   - Add an **HTTP Request** node (`[cred] Supabase - upsert the campaign`), connected from `[cred] Supabase - upsert the job order`. Set method to `POST`, URL to `={{ $('config').first().json.supabase_url }}/rest/v1/campaigns?on_conflict=client_id,idempotency_key`, headers (`apikey`, `Authorization`, `Content-Type`, `Prefer: resolution=merge-duplicates,return=representation`), and body. Enable `neverError` and 3 retries.
   - Add an **HTTP Request** node (`[cred] Supabase - upsert the candidates`), connected from `[cred] Supabase - upsert the campaign`. Set method to `POST`, URL to `={{ $('config').first().json.supabase_url }}/rest/v1/candidates?on_conflict=client_id,ats_candidate_id`, headers (`apikey`, `Authorization`, `Content-Type`, `Prefer: resolution=merge-duplicates,return=representation`), and body. Enable `neverError` and 3 retries.
   - Add a **Code** node (`link the enrollments`), connected from `[cred] Supabase - upsert the candidates`.
   - Add an **HTTP Request** node (`[cred] Supabase - insert the enrollments`), connected from `link the enrollments`. Set method to `POST`, URL to `={{ $('config').first().json.supabase_url }}/rest/v1/enrollments?on_conflict=campaign_id,candidate_id`, headers (`apikey`, `Authorization`, `Content-Type`, `Prefer: resolution=ignore-duplicates,return=representation`), and body. Enable `neverError` and 3 retries.

8. **Add Summary & Notification Nodes:**
   - Add a **Code** node (`build the launch summary`). Connect inputs from both `[cred] Supabase - insert the enrollments` and `STOP: preview - nothing enrolled`.
   - Add an **If** node (`summary configured?`), connected from `build the launch summary`. Set condition to evaluate `{{ $('config').first().json.slack_enabled }} == true`.
   - Add an **HTTP Request** node (`Post the launch summary`), connected to the `true` branch of `summary configured?`. Set method to `POST`, URL to `={{ $('config').first().json.slack_webhook_url }}`, headers (`Content-Type: application/json`), and body payload. Enable `neverError` and 3 retries.
   - Connect the output of `Post the launch summary` and the `false` branch of `summary configured?` to the terminal `End` (`NoOp`) node.
