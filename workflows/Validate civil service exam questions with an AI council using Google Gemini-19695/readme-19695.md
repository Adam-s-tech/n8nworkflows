# Validate civil service exam questions with an AI council using Google Gemini

### 1. Workflow Overview

This workflow implements an automated multi-agent content validation system using Google Gemini to generate, refine, and evaluate civil service examination questions. It follows an iterative refinement loop where a draft question undergoes sequential processing by specialized AI personas, concluding with an automated decision check.

The workflow is grouped into the following functional blocks:
- **1.1 Input Reception & State Initialization:** Manually triggers the execution and establishes initial run parameters (topic, iteration count, feedback).
- **1.2 AI Council Processing Pipeline:** Passes the state sequentially through three Google Gemini nodes functioning as a Generator, Solver, and Examiner.
- **1.3 Parsing & Evaluation Logic:** Extracts, cleans, and parses the structured JSON decision from the Examiner, routing the flow based on approval status and iteration thresholds.
- **1.4 Feedback Loop & Finalization:** Either updates the iteration state to loop back into the generation phase or outputs the final approved question package.

### 2. Block-by-Block Analysis

#### 2.1 Input Reception & State Initialization
- **Overview:** Starts the execution manually and sets up the foundational data variables required for the downstream prompt templates.
- **Nodes Involved:** 
  - `When clicking 'Execute Workflow'`
  - `Initialize State`
- **Node Details:**
  - **When clicking 'Execute Workflow'**
    - *Type and Technical Role:* `n8n-nodes-base.manualTrigger` (Manual Trigger) — Acts as the entry point for manual testing and execution.
    - *Configuration Choices:* Standard manual trigger configuration with no webhook parameters.
    - *Key Expressions/Variables:* None.
    - *Input/Output Connections:* Output connects to `Initialize State`.
    - *Version Requirements:* v1
    - *Edge Cases/Failure Types:* None (manual execution).
  - **Initialize State**
    - *Type and Technical Role:* `n8n-nodes-base.set` (Edit Fields / Set) — Defines initial parameters such as the target topic, feedback strings, and iteration counters.
    - *Configuration Choices:* Sets fields using default options.
    - *Key Expressions/Variables:* Prepares variables accessed downstream like `{{ $json.topic }}` and `{{ $json.iteration }}`.
    - *Input/Output Connections:* Input from `When clicking 'Execute Workflow'`, output to `Generator`.
    - *Version Requirements:* v3
    - *Edge Cases/Failure Types:* Missing required input parameters if not pre-configured.

#### 2.2 AI Council Processing Pipeline
- **Overview:** Executes a three-step generative sequence using Google Gemini to draft, polish, and evaluate a civil service examination question based on feedback history.
- **Nodes Involved:**
  - `Generator`
  - `Solver`
  - `Examiner`
- **Node Details:**
  - **Generator**
    - *Type and Technical Role:* `@n8n/n8n-nodes-langchain.googleGemini` (Google Gemini) — Generates an initial multi-statement multiple-choice question draft.
    - *Configuration Choices:* Uses model ID `models/gemini-3.1-flash-lite`.
    - *Key Expressions/Variables:* `=={{ $json.feedback ? 'Reviewer Feedback: ' + $json.feedback + '\n\n' : '' }}You are an expert exam setter... Generate a question on: {{ $json.topic }}`
    - *Input/Output Connections:* Input from `Initialize State` (or `Update State`), output to `Solver`.
    - *Credentials:* `googlePalmApi` ("Google Gemini(PaLM) Api account 2").
    - *Version Requirements:* v1
    - *Edge Cases/Failure Types:* API rate limits, authentication errors, or model timeouts.
  - **Solver**
    - *Type and Technical Role:* `@n8n/n8n-nodes-langchain.googleGemini` (Google Gemini) — Reviews, debugs, and polishes the draft generated by the previous step.
    - *Configuration Choices:* Uses model ID `models/gemini-3.1-flash-lite`.
    - *Key Expressions/Variables:* Identical prompt structure evaluating preceding context and feedback.
    - *Input/Output Connections:* Input from `Generator`, output to `Examiner`.
    - *Version Requirements:* v1
    - *Edge Cases/Failure Types:* API timeouts, downstream malformed outputs.
  - **Examiner**
    - *Type and Technical Role:* `@n8n/n8n-nodes-langchain.googleGemini` (Google Gemini) — Acts as the strict final judge returning a structured JSON decision object.
    - *Configuration Choices:* Uses model ID `models/gemini-3.1-flash-lite`.
    - *Key Expressions/Variables:* Evaluates the refined question against conceptual clarity criteria.
    - *Input/Output Connections:* Input from `Solver`, output to `Extract JSON String`.
    - *Version Requirements:* v1
    - *Edge Cases/Failure Types:* Failure of the model to output valid JSON text within conversational filler.

#### 2.3 Parsing & Evaluation Logic
- **Overview:** Strips conversational text from the Examiner’s response, parses the embedded JSON decision, and attaches execution metadata.
- **Nodes Involved:**
  - `Extract JSON String`
  - `Parse Decision`
  - `If Rejected & Iteration < 3`
- **Node Details:**
  - **Extract JSON String**
    - *Type and Technical Role:* `n8n-nodes-base.set` (Edit Fields / Set) — Prepares the raw string payload for programmatic extraction.
    - *Configuration Choices:* Standard field mapping options.
    - *Key Expressions/Variables:* Passes raw model text fields.
    - *Input/Output Connections:* Input from `Examiner`, output to `Parse Decision`.
    - *Version Requirements:* v3
    - *Edge Cases/Failure Types:* Empty or missing text fields in upstream responses.
  - **Parse Decision**
    - *Type and Technical Role:* `n8n-nodes-base.code` (Code) — Executes custom JavaScript to isolate JSON blocks using regular expressions and appends parent state metadata.
    - *Configuration Choices:* JavaScript mode parsing `items[0].json`.
    - *Key Expressions/Variables:* 
      ```javascript
      const match = raw.match(/\{[\s\S]*\}/);
      ...
      iteration: $('Initialize State').item.json.iteration, 
      topic: $('Initialize State').item.json.topic
      ```
    - *Input/Output Connections:* Input from `Extract JSON String`, output to `If Rejected & Iteration < 3`.
    - *Version Requirements:* v2
    - *Edge Cases/Failure Types:* Throws explicit runtime error `"No JSON found in response"` if regex matching fails.
  - **If Rejected & Iteration < 3**
    - *Type and Technical Role:* `n8n-nodes-base.if` (If) — Evaluates whether the decision is `"REJECTED"` and the iteration count is strictly less than 3.
    - *Configuration Choices:* Number condition (`iteration` < 3) and String condition (`decision` == `"REJECTED"`).
    - *Key Expressions/Variables:* `=={{ $json.iteration }}` and `=={{ $json.decision }}`.
    - *Input/Output Connections:* Input from `Parse Decision`. True branch outputs to `Update State`; False branch outputs to `Final Approved Output`.
    - *Version Requirements:* v1
    - *Edge Cases/Failure Types:* Type mismatches in comparison values.

#### 2.4 Feedback Loop & Finalization
- **Overview:** Increments run states for iterative re-generation or routes approved items to final storage/output.
- **Nodes Involved:**
  - `Update State`
  - `Final Approved Output`
- **Node Details:**
  - **Update State**
    - *Type and Technical Role:* `n8n-nodes-base.set` (Edit Fields / Set) — Increments iteration variables and passes reviewer feedback back to the generation stage.
    - *Configuration Choices:* Parameter field adjustments.
    - *Key Expressions/Variables:* Prepares updated state values for the next cycle.
    - *Input/Output Connections:* Input from the `True` branch of `If Rejected & Iteration < 3`, output loops back to `Generator`.
    - *Version Requirements:* v3
    - *Edge Cases/Failure Types:* State drift across iterations.
  - **Final Approved Output**
    - *Type and Technical Role:* `n8n-nodes-base.set` (Edit Fields / Set) — Serves as the terminal node returning the successfully approved examination question payload.
    - *Configuration Choices:* Default field return options.
    - *Key Expressions/Variables:* Passes final JSON object.
    - *Input/Output Connections:* Input from the `False` branch of `If Rejected & Iteration < 3`. Terminating node.
    - *Version Requirements:* v3
    - *Edge Cases/Failure Types:* None.

### 4. Reproducing the Workflow from Scratch

1. **Create the Entry Point:**
   - Add a **When clicking 'Execute Workflow'** node (`n8n-nodes-base.manualTrigger`, v1).
2. **Initialize State:**
   - Add an **Initialize State** node (`n8n-nodes-base.set`, v3).
   - Connect `When clicking 'Execute Workflow'` to `Initialize State`.
   - Configure initial fields for `topic` (e.g., string value), `feedback` (empty or null), and `iteration` (set to integer `1`).
3. **Build the AI Council Pipeline:**
   - Add a **Generator** node (`@n8n/n8n-nodes-langchain.googleGemini`, v1).
   - Select model ID `models/gemini-3.1-flash-lite`.
   - Configure Google Gemini credentials (`googlePalmApi`).
   - Set the prompt to incorporate conditional reviewer feedback and request a complex multi-statement multiple-choice question based on `{{ $json.topic }}`.
   - Connect `Initialize State` to `Generator`.
   - Add a **Solver** node (`@n8n/n8n-nodes-langchain.googleGemini`, v1) with the same model configuration. Connect `Generator` to `Solver`.
   - Add an **Examiner** node (`@n8n/n8n-nodes-langchain.googleGemini`, v1) with the same model configuration, prompting it to output a strict JSON decision object containing a `decision` field (`APPROVED` or `REJECTED`) and feedback. Connect `Solver` to `Examiner`.
4. **Setup Parsing and Logic:**
   - Add an **Extract JSON String** node (`n8n-nodes-base.set`, v3). Connect `Examiner` to it.
   - Add a **Parse Decision** node (`n8n-nodes-base.code`, v2). Connect `Extract JSON String` to it.
   - Insert the JavaScript extraction snippet to isolate `{...}` blocks via regex, parsing the JSON and merging `iteration` and `topic` metadata from the `Initialize State` node.
   - Add an **If Rejected & Iteration < 3** node (`n8n-nodes-base.if`, v1). Connect `Parse Decision` to it.
   - Configure the IF node conditions: Number condition where `{{ $json.iteration }}` < `3`, and String condition where `{{ $json.decision }}` equals `"REJECTED"`.
5. **Configure Looping and Output Paths:**
   - Add an **Update State** node (`n8n-nodes-base.set`, v3). Connect the `True` branch of the IF node to `Update State`. Configure it to increment the iteration counter and pass along feedback.
   - Connect `Update State` back to the input of the **Generator** node to close the loop.
   - Add a **Final Approved Output** node (`n8n-nodes-base.set`, v3). Connect the `False` branch of the IF node to it as the terminal success endpoint.
